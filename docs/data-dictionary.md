# Data Dictionary · CE Internship Dashboard

ข้อมูลมี 2 ไฟล์ เชื่อมกันด้วย `studentId` (ไม่ซ้ำ ทั้ง 240 รายการ)

| ไฟล์ | ที่มา | แก้ไขได้หรือไม่ |
| --- | --- | --- |
| `src/data/internships.json` | ข้อมูลต้นฉบับของโปรเจกต์ (แปลงจาก `Computer_Engineering_Internships_2566-2568 (1).xlsx`) ซึ่งระบุไว้ใน metadata ว่าเป็นข้อมูลจำลอง | ไม่แก้ไข เก็บไว้ตามเดิม |
| `src/data/profiles.json` | **ข้อมูลจำลองทั้งหมด** สร้างโดย `npm run data:generate` (seed คงที่ `20251024`) | สร้างใหม่ได้ด้วยคำสั่งเดิม ได้ผลเหมือนเดิมทุกไบต์ |

ค่าว่างใช้ `null` เสมอ และหน้าเว็บแสดงเป็น "ไม่มีข้อมูล" หรือ "ข้อมูลไม่เพียงพอ" ไม่แทนด้วย 0

## internships.json → `students[]` (ต้นฉบับ)

| ฟิลด์ | ชนิด | ความหมาย |
| --- | --- | --- |
| `recordId` | string | รหัสรายการ ไม่ซ้ำ |
| `studentId` | string | รหัสนิสิต (จำลอง `SIM-…`) ไม่ซ้ำ · **คีย์เชื่อม** |
| `academicYearBE` / `academicYearCE` | number | ปีฝึกงาน พ.ศ. / ค.ศ. (ค.ศ. = พ.ศ. − 543) |
| `prefix`, `firstName`, `lastName` | string | ชื่อ (จำลอง) |
| `major` | string | สาขา |
| `interestedRole` | string \| null | **สายงานที่สนใจ** — แยกจากตำแหน่งที่ได้รับจริง |
| `acceptanceStatus` | string | `ได้ที่ฝึกงานแล้ว` หรือ `ยังไม่ได้ที่ฝึกงาน` |
| `applicationStage` | string \| null | ขั้นตอนการสมัคร: `กำลังค้นหา` → `ส่งใบสมัครแล้ว` → `รอสัมภาษณ์` → `รอผลสัมภาษณ์` → `ได้รับการตอบรับ` |
| `accepted` | boolean | `true` เมื่อได้รับการตอบรับ |
| `placement` | object \| null | ที่ฝึกงานที่ได้รับจริง (มีเฉพาะผู้ได้ที่ฝึกงาน) |
| `placement.position` | string \| null | **ตำแหน่งที่ได้รับจริง** |
| `placement.company`, `businessType`, `country`, `province`, `unit`, `department` | string \| null | ข้อมูลสถานประกอบการ |
| `dataType` | string | `ข้อมูลจำลอง` |

### นิยามสถานะ (ใช้ทั้งระบบ)

- **ได้ที่ฝึกงานแล้ว** ⇔ `accepted = true` ⇔ `acceptanceStatus = ได้ที่ฝึกงานแล้ว` ⇔ `applicationStage = ได้รับการตอบรับ` (ตรวจโดย `npm run data:check`)
- **ยังไม่ได้ที่ฝึกงาน** = ทุกขั้นตอนอื่น รวมผู้ที่ยังค้นหาและยังไม่ส่งใบสมัคร
- **อัตราได้ที่ฝึกงาน** = จำนวนผู้ได้รับการตอบรับ ÷ จำนวนนิสิตทั้งหมดในกลุ่ม (ตัวหารรวมทุกขั้นตอน) · กลุ่มที่ตัวหารเป็น 0 แสดง "ไม่มีข้อมูล" ไม่ใช่ 0% · กลุ่มน้อยกว่า 10 คนมีป้าย "ตัวอย่างน้อย"

## profiles.json → `profiles[]` (ข้อมูลจำลองทั้งหมด)

| ฟิลด์ | ชนิด | ช่วงค่า | ความหมาย |
| --- | --- | --- | --- |
| `studentId` | string | — | คีย์เชื่อมกับ `internships.json` |
| `gpa` | number \| null | 0.00–4.00 | GPA สะสม (จำลอง) |
| `skills` | object \| null | — | ระดับทักษะ 12 ด้าน · `null` = ไม่มีผลประเมินทั้งชุด |
| `skills.<skillId>` | integer \| null | 0–5 | ระดับทักษะรายด้าน · `null` = ไม่ได้ประเมินด้านนั้น |
| `portfolio` | object \| null | — | `null` = ไม่มีข้อมูล Portfolio |
| `portfolio.projectCount` | integer \| null | ≥ 0 | จำนวนโครงการ |
| `portfolio.projectTypes` | string[] | — | ประเภทโครงการ: โครงงานรายวิชา, โครงงานส่วนตัว, แข่งขัน / Hackathon, งานชมรม / จิตอาสา, งานฟรีแลนซ์ |
| `portfolio.technologies` | string[] | — | เทคโนโลยีที่ใช้ |
| `portfolio.hasEvidence` | boolean \| null | — | มีหลักฐานผลงานให้ตรวจได้หรือไม่ (repo/demo/เอกสาร) · **ไม่เก็บ URL** |

### วิธีสร้างข้อมูลจำลอง (`scripts/generate-profiles.ts`)

- สุ่มด้วย PRNG mulberry32 seed คงที่ เรียงตาม `recordId` จึงทำซ้ำได้
- **ไม่ใช้สถานะการตอบรับในการสุ่ม** — GPA ทักษะ และ Portfolio ไม่ถูกกำหนดให้สัมพันธ์กับการได้ที่ฝึกงาน ความต่างของอัตราที่เห็นในกราฟจึงเป็นความผันแปรของการสุ่ม ไม่ใช่ข้อค้นพบ
- ทักษะที่อยู่ในเกณฑ์ตัวอย่างของสายงานที่สนใจมีแนวโน้มสูงขึ้นเล็กน้อย เพื่อให้ Heatmap สาธิตได้
- ใส่ค่าว่างโดยตั้งใจ: GPA ≈4%, ทักษะทั้งชุด ≈2%, ทักษะรายด้าน ≈4%, Portfolio ≈5%, จำนวนโครงการ ≈3%, หลักฐานผลงาน ≈8%

## ทักษะและระดับ (`src/lib/skills.ts`)

| skillId | ชื่อ |
| --- | --- |
| `programming` | การเขียนโปรแกรมพื้นฐาน |
| `frontend` | Web Frontend (HTML/CSS/JS/React) |
| `backend` | Backend และ API |
| `database` | ฐานข้อมูลและ SQL |
| `dataAnalysis` | วิเคราะห์ข้อมูลและสถิติ |
| `ml` | Machine Learning |
| `cloud` | Cloud / DevOps |
| `network` | เครือข่ายคอมพิวเตอร์ |
| `security` | ความปลอดภัยไซเบอร์ |
| `testing` | การทดสอบซอฟต์แวร์ |
| `mobile` | พัฒนาแอปมือถือ |
| `git` | Git และการทำงานร่วมกัน |

| ระดับ | ความหมาย |
| --- | --- |
| 0 | ยังไม่มีประสบการณ์ — ยังไม่เคยเรียนหรือลองใช้ |
| 1 | รู้จักแนวคิด — อธิบายแนวคิดพื้นฐานได้ แต่ยังไม่เคยลงมือทำ |
| 2 | ทำตามตัวอย่างได้ — ทำแบบฝึกหัดหรือทำตามบทเรียนได้โดยมีตัวอย่าง |
| 3 | ทำงานเองได้ — ทำโจทย์ทั่วไปหรือโปรเจกต์ขนาดเล็กได้เอง |
| 4 | ประยุกต์ได้ — แก้ปัญหาที่ซับซ้อนขึ้นและเลือกวิธีที่เหมาะสมได้ |
| 5 | แนะนำผู้อื่นได้ — ออกแบบแนวทาง ตรวจงาน หรือสอนผู้อื่นได้ |

## ค่าที่คำนวณ

| ค่า | สูตร |
| --- | --- |
| คะแนนทักษะเฉลี่ย (0–5) | ค่าเฉลี่ยของทักษะที่มีผลประเมิน · ต้องมีอย่างน้อย 6 จาก 12 ด้าน มิฉะนั้นเป็น `null` ("ข้อมูลไม่เพียงพอ") · **ไม่ใช่เปอร์เซ็นต์โอกาสได้ฝึกงาน** |
| Skill Gap รายทักษะ | `max(ระดับเป้าหมาย − ระดับปัจจุบัน, 0)` · ระดับปัจจุบันเป็น `null` → "ข้อมูลไม่เพียงพอ" |
| ลำดับทักษะที่ควรฝึกก่อน | Gap มาก→น้อย, ถ้าเท่ากันเรียงตามระดับเป้าหมายสูง→ต่ำ |
| ช่วง GPA | < 2.50, 2.50–2.99, 3.00–3.49, 3.50–4.00, ไม่มีข้อมูล |
| กลุ่มจำนวนโครงการ | 0, 1–2, 3–4, 5 ขึ้นไป, ไม่มีข้อมูล |

## เกณฑ์ตัวอย่างของสายงาน (`roleBenchmarks`)

เป็น **เกณฑ์ตัวอย่างที่ทีมผู้จัดทำกำหนดเพื่อสาธิต** ไม่ใช่ข้อกำหนดของบริษัทใด และไม่ได้มาจากประกาศรับสมัครจริง
ตำแหน่งฝึกงานในหน้า "สถานประกอบการ" จับคู่กับสายงานผ่าน `positionRole` แล้วแสดงทักษะจากเกณฑ์ชุดเดียวกัน
เปิดดูเกณฑ์ได้ในหน้า "เตรียมความพร้อม" → "ดูเกณฑ์ของสายงานและความหมายของระดับ"
